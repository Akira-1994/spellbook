# A-Z 法術資料庫實作計畫

依據：`docs/superpowers/specs/2026-09-18-az-spell-data-design.md`

## 階段 1：建立解析測試基線

1. 建立測試 fixtures，涵蓋中文條目、英文條目、跨頁條目及同名異效條目。
2. 建立 parser 單元測試，先驗證條目邊界、名稱、規則欄位與頁碼。
3. 建立資料庫測試，驗證外鍵、ULID 格式、名稱非空及 ID 重跑穩定性。

## 階段 2：PDF 擷取與條目切分

1. 使用 `pypdf` 擷取第 192 至 1144 頁文字。
2. 保存逐頁文字與頁碼邊界於暫存目錄。
3. 依字母標題、學派行及 `等級`／`Level` 欄位推斷條目起點。
4. 拼接跨頁正文並保存原文。
5. 產生解析診斷，列出未切分、低信心與欄位缺失條目。

## 階段 3：正規化與資料庫

1. 建立 SQLite schema 與 migration。
2. 實作 `spl_` 加 ULID 的穩定 ID 配發與沿用機制。
3. 正規化名稱、學派、描述符、來源與職業等級。
4. 寫入法術、規則版本與多對多關係。
5. 建立 FTS5 搜尋表與同步重建流程。

## 階段 4：英文條目翻譯

1. 匯出所有英文原文候選條目。
2. 建立文件內術語表。
3. 翻譯名稱、規則欄位、正文與附加代價。
4. 保存英文原文，將翻譯標示為 `generated`／`contextual_glossary`。
5. 將全部英文翻譯列入校對報告。

## 階段 5：JSON、報告與資料字典

1. 由 SQLite 匯出巢狀 `spells.json`。
2. 建立 `spells.schema.json` 並驗證輸出。
3. 產生擷取統計、待校對與翻譯校對報告。
4. 撰寫資料字典與操作說明。

## 階段 6：全量驗證

1. 執行所有單元與整合測試。
2. 驗證 A-Z 完整性、外鍵、唯一 ID、雙語名稱與 PDF 頁碼。
3. 比對 SQLite 與 JSON 的 ID 集合。
4. 抽查每個字母、跨頁、英文翻譯及同名異效條目。
5. 記錄仍需人工判斷的例外，不得以刪除條目方式讓驗證通過。
